# Business_p1 — 다음 거래일 주가 방향 예측

대상일 **09:30 개장 직전까지 이용 가능한 정보**만 사용하여, 전일 종가 대비 대상일 종가의 변화를 5등급으로 예측합니다.

- `0`: 급하락 (`< -2.5%`)
- `1`: 하락 (`-2.5% ~ -0.6%`)
- `2`: 보합 (`-0.6% ~ +0.6%`)
- `3`: 상승 (`+0.6% ~ +2.5%`)
- `4`: 급상승 (`> +2.5%`)

최종 제출 모델은 **대상일 09:29까지 확정된 프리마켓 가격을 사용하는 `gap_z` 규칙**입니다.
09:29 프리마켓 데이터가 없거나 해당 종목의 값을 사용할 수 없는 경우에는 **B0의 시간외 갭 입력값으로 자동 대체**합니다. 분류 경계는 제출 모델의 고정값을 유지합니다.

> 평가 시 추가 학습은 수행하지 않습니다. 제출된 학습 결과와 고정 파라미터만 사용하며,
> 테스트셋에는 예측에 필요한 전처리와 시점별 피처 계산만 수행합니다.

### 1-3. Alpaca API 키 확인 및 `.env` 준비

최종 모델은 Alpaca에서 사전에 수집해 저장한 **대상일 09:29까지의 프리마켓 축약 데이터**를 사용합니다.
수집 단계와 예측 단계를 분리하며, `Model.predict()` 실행 중에는 외부 API를 호출하지 않습니다.

제출 ZIP에는 채점용 Alpaca 키가 들어 있는 **`.env` 파일을 함께 제공합니다.**
프로젝트 루트의 `.env`는 아래 형식입니다.

```dotenv
APCA_API_KEY_ID=발급받은_Key_ID
APCA_API_SECRET_KEY=발급받은_Secret
```

따라서 제출본을 그대로 사용하는 경우 별도의 키 발급 없이 `.env`에 포함된 키를 사용할 수 있습니다.
프리마켓 수집 명령은 프로젝트 루트의 `.env`를 읽습니다. 운영체제 환경변수가 설정돼 있으면 그 값을 우선 사용합니다.
키가 만료·폐기되었거나 별도 키로 재현하려는 경우 아래 절차로 새 키를 발급할 수 있습니다.

#### Alpaca API 키 발급 방법

1. [Alpaca Dashboard](https://app.alpaca.markets/)에서 계정을 만들거나 기존 계정으로 로그인합니다.
2. Alpaca Dashboard에서 **Paper Trading** 계정으로 전환합니다.
3. Dashboard의 **API Keys** 영역으로 이동합니다.
4. **Generate New Key**를 눌러 API Key와 Secret Key를 생성합니다.
5. 생성 직후 두 값을 복사하여 프로젝트 루트의 `.env`에 위 형식으로 입력합니다.
6. Secret Key는 생성 시 한 번만 표시될 수 있으므로 분실했다면 기존 키를 재생성해야 합니다.

Paper Trading용 키와 Live Trading용 키는 서로 다르므로, 본 프로젝트에서는 **Paper Trading 환경에서 발급한 키**를 사용합니다.
프리마켓 수집에는 인터넷 연결이 필요하며, 데이터 시점과 계정의 Market Data 권한에 따라 접근 가능한 실시간 시세 범위가 달라질 수 있습니다.


#### 환경변수를 직접 설정하는 대체 방법

`.env` 대신 운영체제 환경변수를 사용할 수도 있습니다.

**Windows PowerShell**

```powershell
$env:APCA_API_KEY_ID = "발급받은_Key_ID"
$env:APCA_API_SECRET_KEY = "발급받은_Secret"
```

**macOS / Linux**

```bash
export APCA_API_KEY_ID="발급받은_Key_ID"
export APCA_API_SECRET_KEY="발급받은_Secret"
```

### 1-4. 09:29 프리마켓 데이터 준비

이미 평가 대상일의 `artifacts/premarket_0929/` 파일이 준비되어 있다면 이 단계는 건너뜁니다.
새로 수집해야 하는 경우 Alpaca API 키와 네트워크 연결이 필요합니다.
날짜 파일이 있다는 사실만으로 모든 종목의 수집이 끝났다는 뜻은 아닙니다. 아래 기간 명령은 각 날짜에 빠진 종목을 API로 조회하므로, 공개 파일 522개를 배치한 상태에서도 다수의 API 요청이 발생할 수 있습니다. 제공된 캐시만으로 재현할 때는 기간 명령을 실행하지 않아도 됩니다. 수집이 필요하면 먼저 하루·소수 종목으로 요청 범위와 계정 권한을 확인하세요.

최종 제출 코드에서 09:29 수집은 다음과 같이 실행합니다.

```bash
uv run python work/b/features/premarket_rule.py fetch \
  --since <평가에 필요한 첫 기준일> \
  --until <마지막 기준일 다음 경계> \
  --as-of 09:29
```

Windows PowerShell에서는 줄바꿈 대신 한 줄로 실행합니다:

```powershell
uv run python work/b/features/premarket_rule.py fetch --since 2024-08-13 --until 2026-09-12 --as-of 09:29
```

예시:

```bash
uv run python work/b/features/premarket_rule.py fetch \
  --since 2024-08-13 \
  --until 2026-09-12 \
  --as-of 09:29
```

- 날짜 인자는 **기준일** 기준입니다.
- `--until`은 제외 경계입니다. 위 예시는 공개 데이터의 마지막 기준일인 2026-09-11까지 포함하며, 다음 거래일인 2026-09-14의 캐시도 생성합니다. 2026-05-29까지만 지정하면 6~9월 평가에 필요한 캐시가 수집되지 않습니다.
- 09:29 데이터는 `artifacts/premarket_0929/`에 저장합니다.
- API 키는 소스코드나 README 본문에 직접 적지 않고, 제출 ZIP의 루트 `.env`에만 저장합니다.
- 프리마켓 원본 1분봉 전체를 예측 중 다시 조회하지 않습니다.
- 해당 날짜/종목의 분봉이 없거나 수집에 실패하면 예측은 중단되지 않고 B0의 시간외 갭 입력값을 사용합니다.
- 날짜 파일이 이미 있어도 요청한 종목 중 빠진 티커만 추가 수집해 병합합니다. 종목 중복은 제거하고 기존 행을 우선 보존합니다. 수집·저장에 실패하면 기존 파일은 그대로 유지됩니다. 읽을 수 없거나 필수 열이 없는 기존 캐시는 경고 후 보존하므로, 해당 파일을 별도 보관·제거한 뒤 다시 수집해야 합니다.
- 수집 명령은 모든 대상 날짜를 처리하면 종료 코드 `0`, API·캐시 읽기·저장 중 하나라도 실패하면 종료 코드 `1`을 반환합니다. 실패한 날짜의 기존 캐시는 보존됩니다. 분봉이 없어 빈 결과가 나온 경우에는 API 오류와 구별해 예측 시 시간외 갭 입력값을 사용합니다.

**공개 데이터에 없는 새 대상일**은 `dataset/`의 기준일 목록에서 찾을 수 없으므로 대상일과 실제 티커를 직접 지정합니다. 예를 들어 대상일이 `2026-10-14`이고 대상 종목이 AMD와 MSFT라면:

```bash
uv run python work/b/features/premarket_rule.py fetch --target-date 2026-10-14 --symbols AMD,MSFT --as-of 09:29
```

`--target-date`는 여러 번 지정할 수 있습니다. 기존 교수님 데이터의 기준일 목록에서 수집할 때는 위의 `--since`·`--until` 방식을 쓰며, 데이터가 다른 위치라면 `--data <데이터 폴더>`를 추가합니다. 두 방식 모두 수집한 파일은 대상일 이름으로 저장합니다. 종목 코드가 익명 ID라면 Alpaca에서 조회할 수 없으므로 실제 티커 대응표가 필요합니다.

**교수님이 지난 10월 데이터를 받아 일괄 평가하는 경우:** 새 교수님 데이터를 같은 파일 구성·열 형식으로 준비하고, 해당 데이터 폴더를 `--data`로 지정해 평가에 필요한 모든 기준일을 수집합니다. 아래 날짜는 **기준일**의 예시이므로 실제 제공 데이터에서 예측 대상일에 대응하는 기준일 범위를 먼저 확인하세요. 월 첫 거래일을 예측하려면 이전 달의 마지막 거래일도 포함해야 할 수 있습니다.

```powershell
uv run python work/b/features/premarket_rule.py fetch --data <새_데이터_폴더> --since <첫_기준일> --until <마지막_기준일_다음날> --as-of 09:29
```

Alpaca 수집은 프리마켓 축약 파일만 생성합니다. 교수님 형식의 일봉·시간봉과 필요한 과거 가격 이력은 별도로 제공되어야 합니다. 평가일의 캐시를 준비한 후 같은 데이터 폴더로 `check`와 `eval`을 실행합니다.

시험 수집은 `--store <별도 폴더>`를 붙여 원본 캐시와 분리할 수 있습니다. 실제 예측은 `--store` 값을 읽지 않고 `artifacts/premarket_0929/<대상일>.parquet`를 읽습니다. 시험 결과를 사용하려면 파일 내용을 확인한 후 해당 날짜 파일을 그 위치에 배치하세요. 프리마켓 파일명은 **대상일**이며, `main.py predict --date`의 **기준일**과 보통 다릅니다.

**09:30 당일 실시간 사용에는 SIP 데이터 접근 권한이 필요할 수 있습니다.** 무료 계정에서는 최근 SIP 데이터가 지연되므로 09:29 봉을 09:30에 받지 못할 수 있습니다. 이때 파일이 없으면 모델은 시간외 갭 입력값을 사용합니다. 과거 데이터를 나중에 다시 받는 재현과 개장 직전 실시간 수집은 구분해야 합니다. [Alpaca의 데이터 접근 설명](https://docs.alpaca.markets/us/v1.1/docs/market-data-faq)을 확인하세요.

> **주의:** 최종 발표 모델은 09:29 규칙입니다. 제출 ZIP에는 `--as-of 09:29`를 지원하는 최종 수집 코드가 포함되어 있어야 합니다.

### 1-7. 예측 실행

하루 예측 예시:

```bash
uv run python main.py predict --data dataset --date 2026-09-10 --out predictions.csv
```

구간 평가 예시:

```bash
uv run python main.py eval --data dataset --split 2026-06-01 --out evaluation.csv
```

- `--date`는 **기준일**이며 그 다음 거래일을 예측합니다.
- `--split`은 공통 코드의 평가 구간 경계입니다.
- `--split 2026-06-01`은 **예측 대상일**이 2026-06-01 이후인 test 구간입니다. 첫 기준일은 2026-05-29이므로 로그에 5월 기준일이 표시되어도 정상입니다. EDA용 train은 fold4의 train인 기준일 2024-08-13~2026-02-12(377일)이며, 이 실행 절차에서는 EDA나 재학습을 수행하지 않습니다.
- 출력은 `symbol`, `label` 두 열이며 `label`은 `0~4` 정수입니다.
- 예측 시 W&B 로그인, LLM 호출, 모델 재학습은 필요하지 않습니다.

새 평가 데이터를 받을 때도 교수님이 제공하는 일봉·시간봉 등 `dataset/` 형식의 입력이 필요합니다. Alpaca 수집 명령은 프리마켓 축약 파일만 만듭니다. 새 데이터를 기존 `dataset/`과 같은 파일 구성·열 형식으로 준비하고 `--data <새 데이터 폴더>`를 지정하세요. 먼저 그 데이터에 예측할 기준일과 **다음 거래일**이 모두 들어 있는지 확인한 뒤 `main.py predict --data <새 데이터 폴더> --date <기준일>`을 실행합니다. 종목을 제한하려면 `--symbols AMD,MSFT`를 추가할 수 있지만, 새 종목도 해당 데이터의 종목 목록과 필요한 과거 가격에 포함되어야 합니다. 제공 데이터의 마지막 거래일을 기준일로 지정하면 다음 거래일을 찾지 못해 실패합니다. 채점 환경은 `Model.predict(day)` 인터페이스를 호출합니다.

**OpenAI API는 최종 제출 모델의 입력이나 실행 단계가 아닙니다.** 뉴스·LLM 분석은 개발 실험에 사용했지만 제출 예측은 가격 규칙만 사용합니다. 따라서 새 데이터에 대해 OpenAI 호출이나 API 키 설정은 필요하지 않으며, 이 README의 명령으로 OpenAI 결과를 생성하지도 않습니다.

## 3. 최종 모델

### 3-1. 09:29 `gap_z` 규칙

최종 모델은 전일 종가와 대상일 09:29까지 확정된 프리마켓 가격의 갭을 최근 변동성으로 보정합니다.

```text
gap   = (09:29 프리마켓 가격 / 전일 종가) - 1
gap_z = gap / vol20
score = gap_z
```

`vol20`은 해당 기준일까지 관측 가능한 최근 20거래일 수익률로 계산합니다.

최종 제출 파라미터는 다음과 같이 **학습이 끝난 상태로 고정**되어 있습니다.

| 파라미터 | 값 |
|---|---:|
| `lambda` | `0` |
| `a` | `0.07607` |
| `b` | `0.25106` |

예측 등급은 `-b`, `-a`, `a`, `b`를 경계로 나눕니다.

```text
score <= -b       -> 0 (급하락)
-b < score <= -a  -> 1 (하락)
-a < score < a    -> 2 (보합)
a <= score < b    -> 3 (상승)
b <= score        -> 4 (급상승)
```

경계값과 정확히 같으면 양수·음수 모두 더 강한 등급에 포함합니다. 제출 코드의 기존 분류 규칙을 그대로 문서화한 것으로, 파라미터나 예측 동작을 변경하지 않습니다.

평가 시 `lambda`, `a`, `b`를 다시 탐색하거나 평가 정답을 이용해 조정하지 않습니다.

### 3-2. 프리마켓 결측 시 시간외 갭 대체

09:29 분봉 파일이 없거나, 해당 종목이 없거나, 분봉 값을 정상적으로 사용할 수 없는 경우에는
기존 시간외 갭 기반 **B0 입력 피처로 대체**합니다. `a`, `b`, `lambda` 등 분류 파라미터는 프리마켓 제출 모델의 값을 계속 사용하므로 B0 모델의 최종 라벨과 항상 같지는 않습니다.

`artifacts/gapz_rule.json`은 프리마켓 제출 파라미터 파일이 없을 때만 `load_model()`이 사용하는 별도 B0 모델 파일입니다. 평가 중 재학습하지 않습니다.

캐시를 읽을 때도 대상일과 시각을 검사합니다. `t_asof`는 1분 봉의 시작 시각이며, 미국 동부 시간 기준으로 대상일 08:00 이후이고 **봉 종료 시각(`t_asof + 1분`) ≤ 09:29**인 행만 사용합니다. 시간대 없는 시각은 기존 저장 형식에 따라 동부 시각으로 해석하고, UTC 등 시간대가 있는 값은 동부 시간으로 변환합니다.

손상 파일·필수 열 누락은 날짜 전체, 중복 종목·잘못된 가격·잘못된 시각은 해당 종목의 시간외 갭 입력값으로 대체하고 `RuntimeWarning`을 남깁니다. PM 모델의 고정 파라미터는 유지합니다. `px_asof`는 양수인 유한한 가격이어야 합니다. `px_0830`의 결측은 08:30 이전 거래가 없는 기존 정상 캐시에도 존재하므로 허용하지만, 값이 있으면 양수인 유한한 가격이어야 합니다.

## 4. 평가 전에 수행되는 전처리와 학습값 구분

과제 지침에 따라 **학습셋에서 계산해 고정해야 하는 값**과
**평가 데이터 자체에 동일하게 적용할 수 있는 처리**를 명확히 구분합니다.

### 4-1. 학습셋에서 계산한 뒤 평가셋에 그대로 적용하는 값

| 항목 | 학습 시 | 평가 시 |
|---|---|---|
| `lambda`, `a`, `b`, `med`, `sd` | 공개 데이터에서 계산해 확정 | 제출된 고정값 사용. 재학습/재탐색 없음 |
| 별도 B0 모델 파라미터 | 학습 구간에서 계산 | 프리마켓 파라미터 파일이 없을 때만 `artifacts/gapz_rule.json`에서 로드 |
| 모델 선택 | 개발 4폴드에서 완료 | 평가 구간에서는 모델 변경 없음 |

즉, 평가 데이터의 정답 분포나 평가셋 전체 통계량을 이용하여 임계값을 다시 맞추지 않습니다.

### 4-2. 평가셋에 그대로 적용하는 처리

다음 처리는 학습 분포에서 별도 통계량을 fit하는 과정이 아니라, 각 예측 시점에 사용할 수 있는 정보만으로
동일한 규칙을 적용하는 **테스트 시점 전처리/피처 계산**입니다.

| 처리 | 평가 시 동작 |
|---|---|
| 09:29 프리마켓 축약 | 해당 대상일의 09:29까지 끝난 분봉만 사용해 종목별 가격을 저장 |
| `gap` 계산 | 해당 행의 09:29 가격과 전일 종가로 계산 |
| `vol20` | 해당 기준일까지 이미 관측된 과거 거래일 수익률만 이용해 causal rolling 계산 |
| `gap_z` | `gap / vol20`을 종목별로 계산 |
| 결측 처리 / fallback | 해당 날짜·종목의 분봉을 사용할 수 없으면 시간외 갭 입력값 사용. 분류 파라미터는 유지 |
| 5등급 변환 | 학습에서 고정한 `a`, `b`를 그대로 적용 |

`vol20`은 여러 과거 행을 사용하지만 **평가셋 전체의 평균/표준편차를 계산해 스케일링하는 과정이 아닙니다.**
각 예측일마다 그 시점까지 이미 알려진 과거 가격만 사용하는 시계열 피처이며, 미래 행이나 대상일 종가를 사용하지 않습니다.

## 5. 시점 제한 및 데이터 누수 방지

예측 cutoff는 대상일 **09:30**입니다.

교수님 제공 데이터는 `known_at` 기준으로 cutoff 이전에 알 수 있었던 정보만 사용하며,
프리마켓 외부 데이터도 동일하게 09:30 이전에 확정된 값만 사용합니다.

| 데이터 | 사용 규칙 |
|---|---|
| 일봉 | 대상일 일봉은 16:00 이후 확정되므로 사용하지 않음 |
| 1시간봉 | 09:30 시작 봉은 10:30에 끝나므로 09:30 예측에 사용하지 않음 |
| Reddit | 게시 시각이 cutoff 이전인 글만 가능. 36시간 뒤 확정되는 `score`, `n_comments`는 사용하지 않음 |
| 프리마켓 | 대상일 09:29까지 끝난 분봉만 사용 |
| 정답 `day.y` | `predict()` 내부에서 사용하지 않음 |

최종 제출 전 미래 정보 검사를 수행했으며 발표자료 기준 **23,771행에서 미래 정보 사용 0건**을 확인했습니다.

## 6. 학습 및 평가 정책

**평가 과정에서는 학습을 추가로 수행하지 않습니다.**

평가 시 허용되는 작업은 다음과 같습니다.

1. 제출된 고정 파라미터/학습 결과 로드
2. 평가일에 필요한 09:29 프리마켓 데이터 사전 수집·축약
3. 해당 시점 이전 데이터만 이용한 `gap`, `vol20`, `gap_z` 계산
4. 고정 임계값을 이용한 label 변환
5. 분봉 결측 시 시간외 갭 입력값으로 대체

다음 작업은 채점 시 수행하지 않습니다.

1. `fit()` 재실행
2. CV/홀드아웃을 이용한 하이퍼파라미터 재탐색
3. 평가 정답을 이용한 `a`, `b`, `lambda` 수정
4. 평가셋 전체 분포를 사용한 스케일러 재학습
5. W&B/LLM을 이용한 추가 모델 선택

## 8. 홀드아웃 평가 기록

개발 단계에서는 개발 4폴드에서 후보 비교와 모델 선택을 마친 뒤, 확정한 09:29 규칙을 별도로 남겨 둔 홀드아웃에서 독립적으로 평가했습니다.
홀드아웃은 모델 선택이나 보정계수·경계값 조정에 사용하지 않고, 이후 구간의 성능을 확인하는 최종 평가에만 사용했습니다.
아래 표는 이 개발·검증 단계의 기록이며, 최종 제출 준비 단계와 구분합니다.

홀드아웃은 **예측 대상일 기준 2026-06-01~2026-09-14, 73거래일**입니다. 대응하는 기준일은 **2026-05-29~2026-09-11**이며, 50종목 기준 평가 건수는 3,650건입니다.

| 모델 | 홀드아웃 점수 |
|---|---:|
| B0 | 0.5967 |
| 09:15 | 0.5996 |
| 09:28 | 0.6381 |
| **09:29 최종** | **0.6534** |

위 `0.6534`는 개발 단계에서 선택을 마친 규칙의 독립 홀드아웃 평가 기록입니다.

최종 제출 준비 단계에서는 선택한 규칙의 파라미터를 교수님이 공개한 데이터로 다시 학습하여 `artifacts/premarket_rule.json`에 저장했습니다. 현재 제출 JSON의 `main.py eval --split 2026-06-01` 실행은 개발 당시의 별도 홀드아웃 평가와 동일한 실험이 아닙니다. 위 홀드아웃 점수는 현재 JSON의 재실행 점수로 해석하지 않습니다.

교수님의 비공개 10월 평가에서는 이 저장된 JSON을 그대로 읽습니다. 프리마켓 데이터 사전 수집과 예측 시점의 피처 계산만 수행하며, 파라미터를 다시 학습하거나 평가 정답으로 조정하지 않습니다.
