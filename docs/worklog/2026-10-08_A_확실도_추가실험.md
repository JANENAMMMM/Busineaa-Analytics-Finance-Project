## 1. 왜 이렇게 바꿨나 (10/7 결과에서 이어짐)

10/7 에 채민 LLM 피처(뉴스 v6 · Reddit v4)를 그대로 넣은 실험 11개는 전부 실패했음. 가장 큰 단서는
**train 이 LLM 방향을 쓰지 않는 쪽을 골랐다**는 것:

| 10/7 실험 | train 이 고른 값 | 뜻 |
|---|---|---|
| 방향 게이트 (뉴스·Reddit) | 네 폴드 모두 `off` | 엇갈리는 급등락을 낮추면 train 점수가 떨어짐 |
| 방향 더하기 | β = −0.25 / −0.1 / −0.1 / −0.1 (음수) | LLM 이 "좋다" 고 하면 오히려 아래로 조금 밂 |

같은 날 확인한 갭 비교에서도, 갭과 LLM 방향이 엇갈리면 주가는 대부분 갭 쪽으로 갔음 (뉴스 74%).
민영(B)이 독립적으로 잰 값도 같음: 뉴스 부호 일치 0.449, Reddit 0.488 — 동전 던지기 수준 (`docs/review/01_강의대조_점검.md` 4절).

그래서 10/8 에는 **LLM 을 "방향을 알려 주는 것" 이 아니라 "갭이 맞는지 확인해 주는 것" 으로** 바꿈.

```
확실도 = LLM 방향 × 갭 부호        (+ 면 둘이 같은 쪽, − 면 반대)
급등락 경계 b' = b · exp(−δ · z(확실도))      δ 는 train 이 고름, 결측이면 경계 b 그대로
```

δ > 0 이면 "둘이 같은 쪽일 때 급등락으로 더 쉽게 찍는다" 가 됨. 실제로 fold3·fold4 에서 δ = +0.2 가 뽑힘.

근거가 된 강의 내용:
- **w5-1 p25 (Antweiler & Frank 2004), p27 (Kogan et al. 2009)**: 텍스트는 방향이 아니라 움직임의 크기를 예측함 → 방향 대신 경계(크기) 쪽에 쓴다
- **w5-1 p22**: tone 말고도 불확실성·사건·의견 분산을 잴 수 있음
- **w2 p25/p30**: 같은 점수라도 경계를 어디 두느냐가 결정을 바꾸고, 비용이 비대칭이면 경계도 비대칭이어야 함
- **w6-1 p15-18, p23**: permutation importance, 상관 피처 묶기, faithfulness

## 4. 집계 규칙 2개 비교 (강의 w5-1 p16-17, 민영 01 문서 지적)

민영이 "채민 v6 는 비율 하나만 쓴다, 강의는 집계 규칙을 2개 이상 보고하라고 한다" 고 지적함.
또 "뉴스는 피처 값이 있는 날의 85% 가 기사 1~2건이고 `surprise_above_share` 의 93% 가 0 아니면 1" 이라
비율이 사실상 0/1 로 쏠려 있음. 그래서 같은 확실도를 두 방식으로 만들어 비교함.

| 집계 규칙 | f1 | f2 | f3 | f4 | 평균 | 가짜 30회 |
|---|---|---|---|---|---|---|
| 비율판: (상회−하회 비율) × 갭 부호 | 0.4493 | 0.4356 | 0.4056 | 0.5176 | 0.4520 | 0/30 |
| 부호판: sign(상회−하회) × 갭 부호 | 0.4494 | 0.4356 | 0.4034 | 0.5175 | 0.4515 | 0/30 |

**결론이 집계 방식에 의존하지 않음.** fold4 0.5176 vs 0.5175, 평균 0.4520 vs 0.4515.
강의가 요구하는 "두 규칙을 보고하고 결론이 선택에 의존하지 않음을 보여라" 를 충족함.

또 민영 01 문서 4절의 "dev 실적 358건 중 88% 가 예상 상회 → above 는 평범하고 방향 정보는 below 쪽"
을 받아 **하회·하락 의견만** 쓰는 확실도도 해 봄 → 실패 (가짜 14/30).
해석: above 는 방향 정보는 없지만 **행 수를 채우는 역할** 은 함. 빼면 표본이 너무 줄어듦.

## 5. LLM 이 결과를 미리 알았나 (강의 w5-1 p35-37)

Gemini 학습 기간과 우리 데이터 기간(2024-2026)이 겹칠 수 있음. 이름·날짜를 가리고 다시 돌리려면 API 가 필요해서,
대신 **반기별로 신호의 세기가 달라지는지** 를 봄. 과거 기간에서만 유독 잘 맞으면 기억했을 가능성이 큼.

갭과 엇갈릴 때 주가가 LLM 쪽으로 간 비율:

| 기간 | 뉴스 (엇갈린 행) | Reddit (엇갈린 행) |
|---|---|---|
| 2024 하반기 | 37.0% (27) | 32.4% (74) |
| 2025 상반기 | 34.2% (38) | 34.1% (82) |
| 2025 하반기 | **14.3%** (49) | 37.5% (80) |
| 2026 상반기 | 22.8% (57) | 36.7% (79) |

- **Reddit 은 네 기간 모두 32~37% 로 안정적**, 뉴스는 14~37% 로 크게 흔들림.
- 두 출처 모두 **과거 기간이 특별히 더 잘 맞지는 않음** → 모델이 결과를 기억했다는 증거는 안 보임.
- Reddit 이 더 안정적이라는 점은 "둘을 합쳤을 때만 통과" 와도 맞음.
- 한계: 이름·날짜를 가린 재추출(강의가 권하는 본래 방법)은 API 비용 때문에 안 함. 발표에서 한계로 밝힐 것.

## 6. 모델이 LLM 을 얼마나 쓰나 (강의 w6-1 SHAP)

fold4 LightGBM(B 26개 + 채민 46개) 의 TreeSHAP 기여도를 그룹으로 묶음:

| 그룹 | 기여 비중 |
|---|---|
| B 피처 26개 | **98.6%** |
| 뉴스 LLM 26개 | 0.74% |
| Reddit LLM 20개 | 0.63% |

상위 피처는 gap 21.8%, atr14 11.9%, gap_z 9.0%, range1 6.7%, mkt_gap 5.1%.
LLM 중에서는 `news_state_reported_occurred`(0.21%), `reddit_content_type_question`(0.17%), `news_event_earnings`(0.15%).

읽는 법: **모델에 다 넣어 주면 거의 안 씀.** 규칙에서 경계를 움직이는 형태로 **쓰는 자리를 정해 줘야** 신호가 나옴.
이게 "LightGBM + 전부" 는 실패하고 "규칙 + 확실도" 는 통과한 이유로 보임.

## 7. 왜 아직 제출본을 안 바꾸나

| 이유 | 숫자 |
|---|---|
| 채택 기준 미달 | 평균 +0.0019 (기준 +0.005 의 38%) |
| 덮는 행이 적음 | fold4 val 3,000행 중 확실도가 있는 행 **722행** (뉴스만 168 + Reddit 만 446 + 둘 다 108). 그중 값이 0 이 아닌(= 실제로 경계를 움직이는) 행은 **162행**, 급등락이면서 0 이 아닌 행은 **49행** |
| 평가 기간 피처 생성 미정 | 교수님 답변 대기. 우리가 만들어 제출 가능하다고 보지만 절차 미정 |
| 조합이 안 됨 | 경계 분리와 합치면 가짜 30/30 으로 신호 소멸 |

**제안**: 제출본은 B 규칙 v1 유지. 확실도는 발표에서 "근거는 있지만 기준 미달이라 안 넣었다" 로 쓰는 게 정직함.

## 8. 홀드아웃(val) 을 언제 볼 것인가

**지금 보지 말고, 제출 모델을 정한 뒤 한 번만** 보는 것을 제안함.

| 이유 | 근거 |
|---|---|
| 누적 42개 실험을 돌렸음. 지금 보면 다음 실험 선택에 영향을 줌 | 강의 w2 p42 "점수를 본 뒤 경계를 옮기면 테스트 구간이 망가짐" |
| 아직 채택된 게 없음. 홀드아웃은 "정한 것을 확인" 하는 용도이지 "고르는" 용도가 아님 | 같은 슬라이드 |
| 홀드아웃은 73일 × 50종목으로 fold 하나 크기. 이 길이에서는 ±0.03 이 우연히 나옴 | 강의 w2 p29, 10/6 분석 fold4 1σ = 0.029 |

**순서 제안**
1. ~10/10: 채민 데이터 확장 여부 결정. 실험은 4폴드로만 평가
2. 제출 모델 확정 (후보 2개 이하: ① B 규칙 그대로 ② B 규칙 + 확실도) — **어느 쪽을 낼지 미리 정함**
3. 그 직후 홀드아웃 **1회**. 결과와 상관없이 미리 정한 쪽을 냄
4. 홀드아웃 숫자는 발표에 "한 번만 열었다" 와 함께 기록

## 9. 민영(B) 문서에서 받은 것 / 아직 안 한 것
