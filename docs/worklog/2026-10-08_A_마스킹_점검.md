# 2026-10-08 — 기업명이 가려지면 무엇이 깨지나

작성: 남재은 (A) · 브랜치 `jaeeun-llm-news`
대상: 팀 내부 (특히 C 채민 — 추출을 더 돌릴지 결정하는 데 필요)
계기: 10/8 회의에서 "평가 데이터에 기업명이 마스킹돼 있는지 확인해 보겠다" (재은)

---

## 0. 한 줄 요약

- 채민 LLM 파이프라인은 **제목 안의 기업명 문자열**로 기사를 종목에 연결합니다. 이름이 가려지면 **후보가 0건**이 됩니다.
- 반면 데이터가 주는 **`symbols` 열**은 구조화된 값이라 이름이 가려져도 작동하고, **커버리지가 8배 넓습니다**.
- 제출본 B 규칙은 텍스트를 전혀 안 써서 **영향 없음**.
- **제안**: 채민 파이프라인의 기사 선별을 "제목에서 이름 찾기" → "`symbols` 열로 고르기" 로 바꾸면 마스킹에도 견디고 커버리지도 늘어납니다. 보너스로 강의 w5-1 p37 이 권하는 "이름을 가리고 채점" 까지 같이 됩니다.

## 1. 잰 방법

채민 `extraction_spec.json` 의 `aliases`(종목 50개의 기업명·티커 목록)로, 검증 통과 기사의 제목에 그 이름이 실제로 들어 있는지 셌습니다. 그리고 `symbols` 열 기반 경로(`cache/news_titles.parquet`, `day.news()` 의 `symbols` 를 쪼개 연결)와 커버리지를 비교했습니다. dev 기간(기준일 ≤ 2026-05-28)만 봤고 홀드아웃은 안 봤습니다.

후보 선별 조건이 "제목에 기업명이 있을 것" 이라 100% 가 되는 건 당연합니다. 중요한 건 **그래서 이름이 사라지면 통째로 0이 된다**는 점입니다.

|---|---|---|

## 3. 무엇이 깨지고 무엇이 안 깨지나

| 피처 | 마스킹되면 | 이유 |
|---|---|---|
| **제출본 B 규칙** (gap_z, ext_range_z) | **안 깨짐** | 가격·거래 데이터만 씀. 텍스트를 안 봄 |
| 기사 수, tone, A 의 사전 단어 피처 | **안 깨짐** | `symbols` 열로 연결. 제목을 읽기는 하지만 **종목 연결에는 이름이 필요 없음** |
| **채민 LLM 피처 전부** (확실도 포함) | **깨짐** | 후보 선별이 이름 매칭 |

10/8 에 확실도(`llm2_rsize_agree_both`)가 우연 검사를 통과했지만 제출본에 넣지 않기로 한 판단이, 이 점에서도 맞았습니다.

## 4. 채민에게 제안 — 선별 방법만 바꾸면 세 가지가 동시에 해결됩니다

지금:
```
전체 기사 → 제목에 기업명이 있나? → 기대 표현 필터 → LLM
```
바꾸면:
```
전체 기사 → symbols 열이 이 종목을 가리키나? → 기대 표현 필터 → (이름을 ○○○ 로 가리고) LLM
```

| 얻는 것 | 설명 |
|---|---|
| 마스킹에 견딤 | `symbols` 는 데이터가 주는 구조화된 값이라 이름과 무관 |
| 커버리지 8배 | 2,331 → 최대 18,802 칸 (기대 표현 필터를 거치면 줄지만 지금보다는 훨씬 넓음) |
| 모델 기억(contamination) 대응 | 강의 w5-1 p37 "이름·티커·날짜를 가리고 채점하라". 지금 ❌ 인 항목이 같이 해결됨 |
| 기업 연결 오류 감소 | 민영 01 문서가 지적한 약칭·자회사(AWS, Instagram) 문제가 `symbols` 열에서는 애초에 없음 |

비용 주의: 후보가 늘면 호출 수도 늘어납니다. 먼저 **기대 표현 필터까지 거친 뒤 후보가 몇 건인지만 세어** 보고(API 불필요) 예산 안에 들어오는지 확인한 뒤 결정하면 됩니다.

## 5. 한계

- 평가 데이터를 받을 수 없어서 **실제로 마스킹되는지는 모릅니다.** 여기서는 "마스킹된다면 무엇이 깨지는가" 만 쟀습니다.
- 마스킹의 형태도 모릅니다. 티커까지 익명 코드로 바뀌면 `symbols` 열은 여전히 작동하지만(코드로 연결), 제목 안의 회사명은 못 씁니다. 그래도 위 제안은 그대로 유효합니다.
