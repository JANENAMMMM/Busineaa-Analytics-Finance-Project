## 1. git 브랜치 전부를 꼼꼼히 본다 (체크아웃·수정 금지, 읽기만)
팀원별 기여를 빠짐없이 파악하는 게 핵심이다. 한글 파일명이 깨지지 않게 git -c core.quotepath=false 를 쓴다.
읽을 때는 git show <브랜치>:<경로>, git log <브랜치>, git diff --stat origin/main...<브랜치> 를 쓰고 브랜치를 바꾸지 않는다.
먼저 git fetch --all 로 최신화하고, git branch -a --sort=-committerdate 와 git shortlog -sne --all 로 전체 그림을 잡는다.

### W&B 기록도 확인하고 대조·반영한다
프로젝트: BI_finance_project/finance-direction (설정은 lab/wandb.json, 키는 이미 로그인돼 있음). wandb.Api() 로 읽기만 한다.
run 을 새로 만들거나 config·summary·태그를 고치지 않는다.
1) 다 올라갔는지 먼저 확인한다
   - 전체 run 수, 날짜별·job_type별·태그별 분포를 센다. 10/12 기준으로 전체 127개(기존 95 + 백필 32)였다.
   - 10/10 이후 실험은 10/12에 소급 백필했다(tag "backfill", 실제 실험일은 run 이름 앞·태그 orig:<날짜>·config.original_date).
     백필 내역: docs/worklog/2026-10-12_A_지표민감도_WandB점검.md §4~5, scripts/wandb_backfill.py, scripts/wandb_backfill_config.py
   - docs/worklog 의 실험 목록(10-01 ~ 10-12)과 W&B run 을 하나씩 짝지어 "작업일지에는 있는데 W&B에 없는 실험",
     "W&B에는 있는데 작업일지에 없는 run" 을 표로 만든다. 민영·채민 쪽 실험이 W&B에 있는지도 본다.
   - 백필 이후에 다른 세션(예: XGBoost+프리마켓)이 올린 run 이 있으면 그것도 포함한다.
2) 결과 파일과 대조한다
   - 각 run 의 summary(score, train40/fold4/all/score 등)를 해당 reports/ 결과 파일 및 작업일지 숫자와 대조한다.
     예: B0 0.446866 / fold4 0.515419, 홀드아웃 B0 0.596716, P1 0.448532, lgb_cost 0.345979.
   - config 에 folds_hash(기존 run 은 모두 80057b71b4), folds, unseen_symbols, 피처·파라미터·채택 기준이 들어 있는지 본다.
   - 어긋나는 숫자·빠진 설정은 숨기지 말고 불일치 목록에 적는다. 고치지는 말고 나에게 보고한다.
3) 발표 내용에 반영한다
   - 10/2~10/9 의 초기 run(96개 중 다수: v1~v3 규칙 변형, 모델 9종, 손실 6종, 텍스트 실험, LLM2 등)은 작업일지보다 W&B에 더 자세히 남아 있다.
     "몇 개 실험을 했고 몇 개가 B0를 넘었나" 같은 실험 규모·탐색 이력 슬라이드는 W&B 집계로 만든다.
   - W&B 화면(프로젝트 표, 비교 차트)을 발표 그림으로 쓸 만하면 어떤 뷰를 캡처할지 "만들 그림"으로 적는다.
   - 코드 15점·재현성 슬라이드에 실험 추적(W&B: config·git commit·folds_hash 기록)을 근거로 넣는다.
     단 백필 run 은 생성 시각이 10/12라는 점을 숨기지 않고 "기록은 당일 reports/에, W&B 업로드는 소급"이라고 적는다.

## 3. 우리 팀 스토리 후보 (내가 보기에 강조할 것. 근거를 확인한 뒤 순서·비중을 제안해 줘)
1) 지표를 먼저 해부했다: 보합 행 가중 0, 급등락 4배, 반대 방향은 거리 제곱 → "방향 + 급등락"이 점수의 전부라는 설계 출발점 (PDF 13쪽과 연결)
2) 시점을 엄격히 지켰다: known_at 기준 09:30 cutoff, 시간봉 known_at = 봉 끝, Reddit score/n_comments 미사용, walk-forward 4폴드 + 12거래일 embargo,
   학습 40종목/unseen 10종목 분리, 사전 고정 기준, 홀드아웃 1회만 오픈(동결 해시)
3) 단순 갭 규칙(B0)이 ML·텍스트를 이겼다. 이유: 손실의 약 77%가 방향 반대이고, 09:30에 보이는 방향 정보는 사실상 갭뿐
4) 텍스트·LLM은 왜 안 됐는가: 뉴스 내용이 이미 갭에 반영(LLM 방향 52% vs 갭 66%, 갭과 반대일 때 34%). 실패를 수치로 설명
5) 그래서 "더 최신 가격"으로 갔다: 민영의 프리마켓 09:15 분봉 (0.447 → 0.464), 교수님 시간봉 종가 시점 발견
6) 해석의 정직성: 홀드아웃 0.597은 구간 효과(방향 적중 0.551 → 0.691, 개발 어느 폴드보다 높음),
   B0 우위는 급등락 가중 의존(가중 제거 시 −0.0018), B0는 개발 평균 1위가 아니었음 — docs/worklog/2026-10-12_A_세션요약.md §3
7) 수업 내용 활용: 블록 순열 중요도, ALE, ICE, SHAP, 시계열 CV, embargo, bootstrap (reports/lecture_extension/, 10-09 작업일지)
8) 재현성·코드: uv.lock, 테스트, 클린 재현(개발 예측 120,000행 일치), W&B 기록, 제출 형식 검사
이 중 무엇을 메인 스토리로 할지, 무엇을 부록으로 뺄지 제안하고 나에게 확인받는다.

## 4. 반드시 확인해야 할 현재 상태 (추측 금지)

## 6. 꼭 지킬 것
- 홀드아웃(대상일 ≥ 2026-06-01) 정답·점수를 새로 계산하거나 읽지 않는다. 이미 기록된 집계(reports/final_study/holdout_metrics.csv)만 인용한다.
- 브랜치 체크아웃·병합·리셋 금지. 코드·제출 파일은 읽기만 하고 수정하지 않는다. 새로 만드는 파일은 위 md 하나뿐이다.
